# Memory Monitor 内存监控器

## 1. 职责

Memory Monitor 负责监控进程内存使用情况，防止内存溢出（OOM）导致系统崩溃：
- 监控堆内存使用量
- 监控进程 RSS（常驻内存）
- 在内存过高时触发垃圾回收
- 记录内存使用趋势

## 2. 内部工作机制

### 2.1 监控指标

**堆内存（Heap Memory）**

堆内存是 V8/Node.js 管理的 JavaScript 对象内存：
- used_heap_size: 当前使用的堆内存
- heap_size_limit: 堆内存上限
- 使用率 = used_heap_size / heap_size_limit

为什么监控堆内存：
- 堆内存不足是 Node.js 最常见的 OOM 原因
- 可以主动触发 GC 释放内存
- 反映 JavaScript 对象的实际使用情况

**RSS（Resident Set Size）**

RSS 是进程占用的物理内存总量：
- 包含堆内存
- 包含代码段、栈、库
- 包含 Buffer、流等 C++ 分配的内存

为什么监控 RSS：
- 某些内存泄漏发生在堆外（如 Buffer 未释放）
- RSS 超过系统限制会触发 OOM killer
- 更全面的内存使用视图

### 2.2 阈值设置

**堆内存阈值**

- 警告阈值：80%
  - 记录警告日志
  - 提示内存使用偏高
  
- 临界阈值：90%
  - 强制触发垃圾回收
  - 记录 GC 前后内存对比

**RSS 阈值**

- 警告阈值：1.5GB
- 临界阈值：2GB

RSS 临界时触发 GC，虽然 GC 主要释放堆内存，但某些堆外内存与堆对象关联（如 Buffer）。

**GC 触发间隔**

即使内存使用正常，也定期触发 GC：
- 默认间隔：5分钟
- 防止内存缓慢增长
- 保持内存使用平稳

### 2.3 垃圾回收触发

**触发条件**

满足以下任一条件时触发 GC：
1. 堆内存使用率超过临界阈值（90%）
2. RSS 超过临界阈值（2GB）
3. 距离上次 GC 超过间隔时间（5分钟）

**GC 执行**

执行全局垃圾回收：
- 需要 --expose-gc 运行时标志
- 如果没有该标志，GC 函数不可用
- 系统启动时检测 GC 可用性

**GC 效果跟踪**

记录 GC 前后的内存变化：
- 触发前的堆内存使用量
- 触发后的堆内存使用量
- 计算释放的内存量
- 记录释放比例

**GC 后处理**

如果 GC 后内存仍然很高：
- 记录警告日志
- 可能需要进一步处理（如重启）
- 继续正常监控

### 2.4 监控循环

**检查频率**

默认每 30 秒检查一次内存：
- 频率太高会增加 CPU 开销
- 频率太低可能错过内存 spike
- 可配置调整

**检查流程**

每次检查执行以下操作：

1. 获取堆内存统计
   - 调用 memoryUsage()
   - 计算使用率百分比

2. 获取 RSS
   - 从 memoryUsage() 获取 rss 值

3. 判断是否需要 GC
   - 检查堆使用率是否 > 临界阈值
   - 检查 RSS 是否 > 临界阈值
   - 检查是否超过 GC 间隔

4. 执行 GC（如果需要）
   - 记录 GC 前内存
   - 调用全局 GC
   - 延迟后记录 GC 后内存（GC 是异步的）

5. 记录日志
   - 记录当前内存使用
   - 如果触发 GC，记录释放量
   - 使用结构化日志格式

**异常处理**

检查过程中捕获异常：
- 防止监控器崩溃影响主系统
- 记录错误日志
- 继续下一次检查

### 2.5 内存报告

**日志格式**

内存使用日志包含：
```
Memory check - Heap: 45% (230MB / 512MB), RSS: 450MB
```

GC 报告包含：
```
Memory GC triggered - Heap: 90% before, 65% after, freed: 128MB
```

**报告内容**

- 堆内存使用量和百分比
- RSS 使用量
- GC 触发原因（阈值/间隔）
- GC 释放的内存量
- 时间戳

### 2.6 启动参数检测

**GC 可用性检测**

系统启动时检测是否可以使用 GC：
- 检查全局 global.gc 函数是否存在
- 如果存在，说明有 --expose-gc 标志
- 如果不存在，GC 功能被禁用

**警告提示**

如果没有 --expose-gc：
- 记录警告日志
- 内存监控仍然运行（只读）
- 不会自动触发 GC
- 建议用户添加启动参数

### 2.7 配置

```json
{
  "memoryMonitor": {
    "enabled": true,
    "checkIntervalMs": 30000,
    "gcIntervalMs": 300000,
    "heapWarningThreshold": 0.8,
    "heapCriticalThreshold": 0.9,
    "rssWarningThreshold": 1610612736,
    "rssCriticalThreshold": 2147483648
  }
}
```

### 配置项说明

- enabled: 是否启用内存监控
- checkIntervalMs: 检查间隔（毫秒）
- gcIntervalMs: 定期 GC 间隔（毫秒）
- heapWarningThreshold: 堆内存警告阈值（0-1）
- heapCriticalThreshold: 堆内存临界阈值（0-1）
- rssWarningThreshold: RSS 警告阈值（字节）
- rssCriticalThreshold: RSS 临界阈值（字节）

## 3. 使用场景

### 3.1 长期运行的智能体

智能体可能运行数小时甚至数天：
- 消息历史不断增长
- 对话上下文累积
- 内存缓慢增长

内存监控确保：
- 定期 GC 释放不再使用的内存
- 在内存过高前预警
- 防止 OOM 崩溃

### 3.2 高并发场景

多个智能体同时运行：
- 内存使用峰值更高
- 需要更频繁的监控
- 可能需要调整阈值

### 3.3 内存泄漏检测

如果 GC 后内存仍然很高：
- 可能存在内存泄漏
- 需要分析堆快照
- 可能需要重启服务

## 4. 注意事项

### 4.1 GC 不是万能的

垃圾回收只能回收不再引用的对象：
- 如果对象仍被引用，不会回收
- 内存泄漏（如全局缓存无限增长）需要代码修复
- GC 有性能开销，不宜过于频繁

### 4.2 RSS 包含堆外内存

RSS 包括：
- 堆内存
- Buffer 分配的内存
- 加载的库
- 线程栈

某些内存不由 GC 管理，需要其他手段释放。

### 4.3 阈值调优

不同场景需要不同的阈值：
- 内存充足的机器可以放宽阈值
- 内存紧张的机器需要更严格的阈值
- 根据实际运行数据调整

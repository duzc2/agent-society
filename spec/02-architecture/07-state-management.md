# 状态管理

## 状态分类

**运行时状态（内存）**
- 智能体实例（Agent 对象）
- 消息队列
- 当前运算状态
- 对话历史缓存

运行时状态在系统重启后丢失，需要从持久化状态恢复。

**持久化状态（文件）**
- 智能体元数据（岗位、父智能体、创建时间等）
- 组织关系
- 消息历史（JSON Lines 格式）
- 对话历史
- 自定义名称

**配置状态（文件）**
- 应用配置（app.json）
- LLM 服务配置
- 日志配置

## 状态恢复流程

系统启动时的状态恢复：

1. **加载配置**：Config 服务加载 app.json 和 app.local.json
2. **恢复组织关系**：从 org.json 加载岗位定义和智能体关系
3. **恢复智能体元数据**：遍历 agents/ 目录，加载每个智能体的配置
4. **恢复对话历史**：ConversationManager 加载对话记录
5. **恢复消息历史**：HTTP Server 预加载消息文件到内存索引
6. **创建 Root 智能体**：如果不存在，创建新的 Root 智能体
7. **启动消息处理循环**：RuntimeMessaging 开始处理消息

## 状态持久化策略

**即时持久化**
- 消息发送时立即追加到 JSON Lines 文件
- 智能体创建/删除时立即更新 org.json
- 自定义名称修改时立即保存

**延迟持久化**
- 对话历史每 10 条消息或 5 分钟保存一次
- 智能体状态（如 token 使用）定期批量保存

**故障恢复**
如果系统在运行中崩溃，持久化的状态可以保证：
- 已发送的消息不会丢失
- 智能体组织关系完整
- 对话历史最多丢失最近几条

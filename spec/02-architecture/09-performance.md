# 性能设计

## 并发模型

**消息处理并发**
- 每个智能体的消息按顺序处理（单线程语义）
- 不同智能体并发处理
- 通过 asyncio.Semaphore 限制并发数（默认 50）

**LLM 调用并发**
- 全局限制并发 LLM 请求数（默认 2）
- 防止触发 API 限流
- 超出限制的请求排队等待

**文件 I/O 并发**
- 使用 aiofiles 实现异步文件操作
- 大文件读写不阻塞消息处理

## 内存管理

**消息历史管理**
- 消息持久化到文件，内存只保留索引
- HTTP 查询时按需加载
- 定期清理过期消息（可配置保留时间）

**对话历史压缩**
- 当 token 数超过阈值，自动压缩历史
- 保留 system 消息和最近消息
- 压缩策略可配置

**智能体资源释放**
- 长时间空闲的智能体释放对话缓存
- 被删除的智能体清理所有关联数据

## 缓存策略

**配置缓存**
- 配置加载后缓存到内存
- 文件变更时通过监听或定期检查刷新
- 支持手动清除缓存

**对话缓存**
- 活跃智能体的对话缓存到内存
- 不活跃智能体的对话只保留在文件

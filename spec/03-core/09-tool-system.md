# Tool System 工具系统

## 1. 工具定义

### 1.1 工具结构

工具包含以下属性：
- `name`：唯一标识
- `description`：功能描述（用于 LLM 理解）
- `parameters`：参数定义（OpenAI function calling 格式）
- `handler`：处理函数
- `group`：所属工具组

### 1.2 参数定义格式

使用 JSON Schema 子集定义参数：

结构要求：
- type 必须为 "object"
- properties 定义各个参数及其类型
- required 数组列出必填参数

参数类型支持：
- string：字符串
- integer：整数
- number：数字
- boolean：布尔值
- array：数组
- object：对象

每个参数可以包含：
- description：参数说明
- enum：枚举值列表
- default：默认值

示例参数定义：
```json
{
  "type": "object",
  "properties": {
    "to": { 
      "type": "string", 
      "description": "目标智能体ID" 
    },
    "message": { 
      "type": "string", 
      "description": "消息内容" 
    }
  },
  "required": ["to", "message"]
}
```

## 2. 工具注册

### 2.1 注册时机

工具在系统启动时注册：
1. 内置工具：Runtime 初始化时注册
2. 模块工具：模块加载时注册

### 2.2 注册流程

注册工具时执行以下步骤：

1. **验证工具名称**
   - 检查名称是否已存在
   - 如果存在，抛出错误或覆盖（取决于配置）
   - 名称必须唯一，作为工具的标识

2. **验证参数定义**
   - 检查 JSON Schema 格式是否合法
   - 验证 type 字段必须为 "object"
   - 检查 properties 是否为对象
   - 验证 required 是否为字符串数组
   - 递归验证嵌套结构

3. **存储到注册表**
   - 将工具定义存储到内存映射中
   - 键为工具名称
   - 值为完整的工具定义对象

4. **加入分组**
   - 根据 group 字段将工具加入对应分组
   - 如果分组不存在，创建新分组
   - 同一工具只能属于一个分组

### 2.3 注册表查询

工具注册表支持以下查询方式：

按名称查询：
- 输入工具名称
- 返回工具定义或 null（不存在）

按分组查询：
- 输入分组名称
- 返回该分组下所有工具定义列表

查询所有分组：
- 返回所有分组名称列表
- 用于展示工具组织结构

## 3. 工具组

### 3.1 工具组定义

工具组是对工具的归类，岗位配置使用工具组而非单个工具。

内置工具组：
- `org_management`：组织管理（创建角色、删除智能体等）
- `workspace`：工作空间（文件读写、目录操作等）
- `execution`：代码执行（run_javascript、run_python）
- `communication`：通信（send_message）
- `llm`：LLM 工具（ask_llm）

### 3.2 工具组用途

简化岗位配置：
- 岗位只需声明需要的工具组
- 自动获得该组所有工具
- 避免逐个配置工具

权限控制：
- 按组控制智能体的工具权限
- 支持通配符（如 workspace.*）
- 便于批量授权

模块化扩展：
- 新工具加入现有分组即可被使用
- 无需修改岗位配置
- 支持动态注册新分组

## 4. 工具调用

### 4.1 调用流程

当收到工具调用请求时，执行以下流程：

1. **权限验证**
   - 获取调用者智能体的配置
   - 检查 allowed_tools 字段
   - 如果为空列表，允许所有工具（向后兼容）
   - 如果工具名在列表中，允许调用
   - 如果分组通配符匹配，允许调用
   - 否则返回权限拒绝错误

2. **查找工具**
   - 根据工具名称查询注册表
   - 如果未找到，返回工具不存在错误
   - 获取工具的完整定义

3. **参数验证**
   - 获取工具定义的参数 schema
   - 验证传入的参数是否符合 schema
   - 检查必填参数是否存在
   - 验证参数类型
   - 验证枚举值
   - 返回详细的验证错误信息

4. **执行工具**
   - 构建 ToolContext（包含 runtime、agent_id 等）
   - 调用工具的处理函数
   - 传入验证后的参数和上下文
   - 等待执行完成或超时

5. **结果处理**
   - 如果执行成功，返回结果
   - 如果执行失败，返回错误信息
   - 记录执行日志
   - 截断过大的结果

### 4.2 错误处理

权限不足：
- 错误类型：PermissionDenied
- 消息："智能体没有权限使用工具 {tool_name}"
- 返回给 LLM，由 LLM 决定如何处理

参数无效：
- 错误类型：ValidationError
- 消息包含具体字段和期望类型
- 示例："参数 'to' 必须是字符串"

执行异常：
- 捕获所有异常
- 记录详细错误日志（包含堆栈）
- 返回友好错误信息（不包含敏感细节）
- 错误信息示例："文件写入失败：磁盘空间不足"

## 6. 数据接口

### 6.1 工具定义结构

工具定义包含：
- name: 字符串，工具唯一名称
- description: 字符串，功能描述
- parameters: 对象，JSON Schema 格式
- handler: 函数，异步处理函数
- group: 字符串，所属分组

### 6.2 工具调用结构

工具调用请求包含：
- id: 字符串，调用唯一标识
- name: 字符串，工具名称
- arguments: 对象，参数键值对

### 6.3 工具结果结构

工具执行结果包含：
- tool_call_id: 字符串，对应调用的ID
- success: 布尔值，是否成功
- result: 任意类型，成功时的返回值
- error: 字符串，失败时的错误信息

结果构造方式：
- 成功：设置 success=true，填写 result
- 失败：设置 success=false，填写 error

### 6.4 工具注册表接口

工具注册表提供以下操作：

注册工具：
- 输入：工具定义
- 处理：验证并存储
- 输出：无（或成功/失败状态）

查询工具：
- 输入：工具名称
- 输出：工具定义或不存在标记

按分组查询：
- 输入：分组名称
- 输出：该分组下所有工具定义列表

列出分组：
- 输入：无
- 输出：所有分组名称列表

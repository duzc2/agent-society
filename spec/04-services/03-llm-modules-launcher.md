# LLM-Modules Launcher LLM模块启动器

## 1. 职责

LLM-Modules Launcher 负责管理本地 Python Embedding 服务的生命周期：
- 检测是否需要启动本地服务
- 管理服务进程（启动、停止、健康检查）
- 跨平台支持（Windows / Linux / macOS）

## 2. 内部工作机制

### 2.1 服务状态管理

服务具有以下状态：
- **idle**: 初始状态，未启动
- **starting**: 正在启动中
- **ready**: 已启动并就绪
- **error**: 启动失败或运行出错

状态转换流程：
```
idle → starting → ready
            ↓
          error
```

从 error 状态可以通过重试回到 starting 状态。

### 2.2 本地服务检测

系统启动时检测配置中的 Embedding 服务地址：

**检测逻辑**

检查配置的 baseUrl 是否为本地地址：
- localhost
- 127.0.0.1
- 0.0.0.0（绑定所有接口）
- 其他本地回环地址

如果是本地地址，则需要启动 LLM-Modules 服务；如果是远程地址，则跳过启动。

**多服务处理**

如果配置了多个 Embedding 服务，只检查第一个本地服务。如果所有服务都是远程的，不启动本地服务。

### 2.3 启动流程

**启动条件检查**

启动前确认：
1. 配置中确实存在本地 Embedding 服务
2. 当前状态为 idle 或 error（避免重复启动）
3. 虚拟环境目录存在
4. 启动脚本存在

**跨平台启动**

根据操作系统选择不同的启动方式：

*Windows 平台*
- 使用 cmd.exe /c 执行批处理命令
- 激活虚拟环境后执行启动脚本
- 命令序列：激活venv → 安装依赖 → 启动服务

*Unix 平台（Linux/macOS）*
- 使用 bash -c 执行 shell 命令
- 同样的命令序列
- 处理不同的路径分隔符和权限

**启动脚本**

启动流程执行以下步骤：
1. 激活虚拟环境（source venv/bin/activate 或 venv\Scripts\activate）
2. 安装/更新依赖（pip install -r requirements.txt）
3. 启动服务进程（python start.py）

**进程创建**

使用子进程创建服务：
- 设置工作目录为 LLM-Modules 目录
- 重定向 stdout 和 stderr 到管道
- 继承环境变量，添加虚拟环境路径
- 设置进程组（便于后续整体终止）

### 2.4 健康检查

**检查机制**

服务启动后需要确认是否真正就绪：

*方式一：HTTP 健康端点*
- 轮询 /health 端点
- 期望返回 200 状态码
- 超时时间：60秒
- 轮询间隔：500毫秒

*方式二：日志检测*
- 监听服务进程的 stdout
- 检测 "Uvicorn running on" 字样
- 表示服务已成功启动

**就绪确认**

任一方式检测到服务就绪后：
- 更新状态为 ready
- 记录启动耗时
- 通知等待者服务已就绪

### 2.5 停止流程

**停止触发时机**

- 系统关闭时（SIGTERM / SIGINT）
- 配置变更需要重启服务
- 健康检查持续失败

**优雅停止**

停止流程遵循优雅关闭原则：
1. 发送 SIGTERM 信号给服务进程
2. 等待进程自然退出（超时30秒）
3. 如果超时未退出，发送 SIGKILL 强制终止
4. 清理子进程（防止孤儿进程）

**Windows 特殊处理**

Windows 不支持 SIGTERM，使用以下方式：
- 发送 Ctrl+C 信号（GenerateConsoleCtrlEvent）
- 或者直接终止进程树

### 2.6 自动重连

**错误恢复**

如果检测到服务崩溃或不可达：
1. 更新状态为 error
2. 记录错误日志
3. 触发自动重连（如启用）

**重连策略**

- 指数退避重试（1秒 → 2秒 → 4秒 → 最大60秒）
- 最大重试次数可配置
- 重试期间标记服务不可用

### 2.7 并发控制

**单例启动**

确保同一时间只有一个启动流程：
- 使用锁保护启动过程
- 多次调用 ensureReady 返回相同 Promise
- 避免重复启动多个实例

**等待机制**

如果服务正在启动中，后续调用进入等待队列：
- 等待状态变为 ready 或 error
- 设置超时防止永久等待
- 返回就绪状态或抛出错误

## 3. 配置

### 3.1 配置项

```json
{
  "embedding": {
    "baseUrl": "http://localhost:1234/v1",
    "timeout": 60
  },
  "llmModules": {
    "autoStart": true,
    "maxRetries": 3,
    "healthCheckTimeout": 60
  }
}
```

### 3.2 环境变量

- LLM_MODULES_PATH: LLM-Modules 目录路径
- LLM_MODULES_VENV: 虚拟环境目录（默认自动检测）

## 4. 故障处理

### 4.1 启动失败

**常见原因**
- 虚拟环境不存在或损坏
- 依赖安装失败
- 端口被占用
- Python 版本不兼容

**处理策略**
- 详细记录错误输出
- 清理不完整的进程
- 状态设置为 error
- 通知上层服务不可用

### 4.2 运行时崩溃

**检测方式**
- 进程退出码非0
- 健康检查连续失败
- 日志中出现错误关键字

**处理策略**
- 记录崩溃原因
- 自动尝试重启（如启用）
- 如果重启失败，降级为 error 状态

### 4.3 端口冲突

如果配置的端口已被占用：
- 服务启动会失败
- 日志显示绑定错误
- 需要用户手动修改配置或释放端口

## 5. 日志输出

**日志级别**

- debug: 详细的启动过程信息
- info: 状态变更、健康检查结果
- warning: 重试、降级等警告
- error: 启动失败、崩溃等错误

**日志内容**

包含以下信息：
- 启动命令
- 进程ID
- 健康检查轮询记录
- 服务就绪确认
- 停止信号发送和确认

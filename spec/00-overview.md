# Agent Society 项目概述

## 项目愿景

Agent Society 是一个基于大语言模型的智能体自组织系统。核心目标是让智能体能够像人类一样形成自组织的社会性团体，通过分工协作完成复杂任务。

**核心价值主张**：
- 用户只需提出自然语言需求，系统自动分解并执行
- 智能体能够自主决策、创建子任务、分配给其他智能体
- 支持多层级组织架构，类似人类企业的部门体系
- 智能体间通过异步消息通信，支持中断和延迟投递

## 核心特性

- **自组织**: 智能体能够自主创建子岗位和子智能体
- **层级管理**: 支持多层级组织架构
- **异步通信**: 智能体间通过消息总线异步通信，支持插话机制
- **工具扩展**: 支持通过工具组动态扩展能力
- **技能学习**: 智能体可以自主学习新技能
- **长期记忆**: 基于向量检索的智能体长期记忆
- **多模态支持**: 图片、文件附件的内容路由和处理

## 核心概念

### User（用户）
系统的使用者，通过自然语言与系统交互。系统在用户侧表现为一个"User"智能体，作为用户与整个智能体社会的接口。

### Root 智能体
系统的入口智能体，负责理解用户需求并分解任务。Root 本身不执行具体任务，而是组织其他智能体完成工作。

### 智能体（Agent）
具有特定角色和能力的执行单元。每个智能体属于一个岗位（Role），具有唯一标识和独立状态。智能体可以：
- 接收和发送消息
- 调用工具
- 请求 LLM 生成响应
- 创建子智能体

### 岗位（Role）
智能体的角色定义，包含职责描述（prompt）和可用工具权限。岗位可以形成层级关系。

### 组织（Organization）
智能体的层级结构，支持多层级树状组织。组织关系动态变化，智能体可以创建或删除其他智能体。

### 消息总线（Message Bus）
智能体间异步通信的基础设施。每个智能体有自己的消息队列，支持延迟投递和消息中断机制。

### 任务（Task）
用户提交的需求对应一个任务。任务有唯一标识，相关消息都关联到该任务。

## 设计原则

**自组织原则**
系统启动时只有 Root 智能体。当用户提交需求后，Root 根据需求创建子岗位和子智能体。

**异步通信原则**
智能体间通信完全异步。发送方不等待接收方处理完成，消息进入接收方队列等待处理。

**工具权限隔离原则**
每个岗位配置可用的工具组。Root 岗位只能使用组织管理工具，普通智能体可以使用文件操作、代码执行等工具。

**状态持久化原则**
智能体状态、消息历史、对话记录都持久化到文件系统。系统重启后可以恢复上次状态。

### 阶段 3: 服务层 (3 周)

- Conversation 服务
- Workspace 服务
- Tool 执行器

### 阶段 4: HTTP API (2 周)
- HTTP Server 实现
- 所有 API 端点

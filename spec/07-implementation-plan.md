## 4. 关键设计决策

### 4.1 为什么用 FastAPI 而不是 Flask？

- **原生异步支持**：FastAPI 基于 Starlette，原生支持 async/await
- **自动数据验证**：Pydantic 集成，自动验证请求/响应
- **自动文档生成**：OpenAPI 文档自动生成
- **类型安全**：完整的类型注解支持

### 4.2 为什么用 Pydantic v2？

- **性能提升**：v2 比 v1 快 5-50 倍
- **更好的类型支持**：更完善的类型注解
- **生态系统**：主流库都已迁移到 v2

### 4.3 为什么用 Playwright 而不是 Selenium？

- **自动等待**：元素操作自动等待，减少 flaky 测试
- **多浏览器支持**：Chromium、Firefox、WebKit
- **更好的 API**：更现代的 API 设计
- **自动安装**：自动下载浏览器二进制文件

### 4.4 为什么用 NDJSON 而不是 SQLite？

- **简单**：无需外部依赖
- **追加友好**：O(1) 追加性能
- **可读**：人类可读的格式
- **版本控制友好**：便于查看变更

未来可以支持 SQLite 作为可选存储后端。

## 5. 质量保障

### 5.1 代码规范

- **类型注解**：所有公共函数必须有类型注解
- **文档字符串**：所有公共类和方法必须有 docstring
- **代码格式化**：使用 black 格式化
- **代码检查**：使用 ruff 检查

### 5.2 测试策略

**单元测试**
- 测试单个函数/类
- 使用 mock 隔离依赖
- 覆盖率 > 80%

**集成测试**
- 测试模块间协作
- 使用临时目录
- 验证端到端流程

**E2E 测试**
- 启动完整服务
- 通过 HTTP API 测试
- 验证与原前端兼容

### 5.3 代码审查

- 所有代码提交前必须审查
- 使用 Pull Request 流程
- 自动 CI 检查（测试、类型检查、代码格式）

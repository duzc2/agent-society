# 开发规范

本篇汇总项目强制的工程约定。这些规则同时写在根级 `CLAUDE.md` / `AGENTS.md`，对人类贡献者与 AI 协作者同样生效。

## 代码组织

- **单文件 ≤ 500 行**（不含注释），超限按职责拆分；
- 模块化：每个模块只负责一项功能，高内聚低耦合，避免循环依赖；
- 目录层级 ≤ 3 层；
- 代码按文件夹区分：数据、配置、源码、测试；
- **每个目录有同名 `.md` 说明文件**（综述/文件列表/子目录列表）；
- 测试目录结构与源码镜像（`src/platform/services/llm/` ↔ `test/platform/services/llm/`）。

## 空值纪律（铁律）

**功能性组件（服务、管理器、注册表、注入的依赖对象）禁止空值兼容**：

```javascript
// ❌ 错误：对依赖对象做空值兼容，掩盖初始化 bug
this._registry = options.lifecycleRegistry ?? null;
if (this._registry) { this._registry.register(...); }

// ✅ 正确：依赖直接使用，缺了让它炸出来
this._registry = options.lifecycleRegistry;
this._registry.register(...);
```

- 空值兼容**仅允许**用于：用户输入、文件内容、API 响应、配置参数（字符串/布尔/数值/阈值）等外部数据；
- 判断依据：这东西是程序自己构建/注入的（必须保证有值），还是外部来的（允许容错）。

## 异常处理（铁律）

1. 任何 `catch` 必须输出完整日志：`message` + `stack` + 业务上下文（URL、method、参数）；
2. 禁止 `catch (_err)`、`catch {}` 吞异常；
3. 回退之前必须先 `log.error(...)` 记录原始异常；
4. 有全局异常捕获（uncaughtException / unhandledRejection），同样打足日志（见 `start-wrapper.mjs` 与 `start.js` 的做法）；
5. 处理顺序：先原始方式打印日志 → 维护现场防扩散 → 向协议/UI 传友好错误信息（可读、无敏感信息、说明哪个功能因什么原因失败）。

## 注释规范

- 每个函数都要有注释：**为什么这么设计、满足什么需求、关键约束、关键保护点**，不是复述代码；
- 重点算法函数内部也要写注释；
- 文件头部写模块说明（职责、设计初衷、主要功能）；
- 语言：默认中文（UTF-8）；目标运行时不支持中文注释时用英文。

## 接口与设计

- 先设计工作流程，再设计接口；从使用者角度设计接口；
- 每个模块对自身功能全权负责，职责不外溢：判断"要不要调用某模块"只用自己掌握的数据，让对方自己判断；
- 模块间最小知道原则；流程上有数据修改的环节要明确引用还是复制；
- 复用看语义：语义与环境相同的要扩展复用；语义不同的即使代码一样也不复用；
- 重复三次的语义模式要提设计模式重构；不堆 ifelse/switch，用流程与结构保证正确性；
- 新增功能优先复用已有机制（通信、事件、文件），不新建平行体系。

## 日志规范

- 用 `runtime.loggerRoot.forModule("<模块名>")` 获取模块 logger；
- 级别经 `config/logging.json` 按模块控制；
- 结构化日志：`log.info("消息", { key: value })` 形式，便于检索；
- 关键生命周期事件（智能体创建/终止、LLM 调用指标）有专门的日志方法（`logAgentLifecycleEvent` / `logLlmMetrics`）。

## 测试规范

- `npm test` 运行（禁裸 `node --test`）；
- 每个功能改动必须带测试；测试覆盖正确性 + 鲁棒性（边界、异常、并发）；
- 通信协议按"编码→存文件→解码→比对"模式测试；
- 测试参数多样：合理/随机/错误/边界；
- 小步提交：模块完成即测，测过即接入系统实测，再做人工验证。

## Git 与流程

- **所有 git 操作（commit/push/restore）必须经人工确认**，任何自动化工具不得自行执行；
- 每次代码修改完成后：运行 `npm test` → 停下 → 报告结果 → 等待明确许可再继续；
- 不轻易移动文件；遵循已有代码的风格、命名、约定，不另起一套。

## 依赖管理

- 新增依赖需说明理由；`package.json` 的 `overrides` 管理安全版本下限；
- 运行时依赖尽量少（当前核心依赖：hono、ai-sdk 系列、openai、ssh2、puppeteer-core 等）；
- `npm audit --production` 作为发布前检查（CI 已集成）。

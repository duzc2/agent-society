# 数据与目录

知道数据放在哪，便于备份、迁移、清理。

## 数据位置

| 位置 | 内容 |
|------|------|
| `agent-society-data/`（项目根目录下） | 所有运行数据：组织状态、工作区文件、记忆、日志 |
| `config/` | 配置文件 |

启动时可用参数指定数据目录位置（见[安装与启动](02-installation.md)）。

## 目录内容

```
agent-society-data/
├── org/            # 组织状态：岗位、智能体、层级关系
├── agents/         # 智能体运行数据
├── agent-memory/   # 向量记忆
├── workspaces/     # 每个任务一个子文件夹：任务的产出文件都在这里
├── runtime/
│   ├── state/      # 会话历史
│   └── logs/       # 运行日志
├── logs/           # 启动日志、退出原因
├── skills/         # 技能
└── …               # 其余为各模块运行数据
```

日常打交道最多的是 `workspaces/`——你上传的文件、智能体的产出都在里面，界面的**工件**面板就是它的可视化。

## 文件访问范围

- 默认只能访问任务工作区；
- 要让它读工作区之外的文件（如 "分析 D 盘数据目录里的 csv"）：界面 → 工作区文件访问面板 → 添加授权文件夹；
- 每次外部文件访问都有记录，可在面板中查看。

## 备份与迁移

| 目的 | 做法 |
|------|------|
| 完整备份 | 复制整个 `agent-society-data/` |
| 只要某任务的文件 | 复制 `workspaces/<任务对应文件夹>/` |
| 迁移到新机器 | 新机器装好项目 → 拷贝数据目录和 `config/*.local.json` → 启动 |

## 清理

- 旧任务的工作区不会自动删除，不需要的可从 `workspaces/` 删除（或在界面工件面板确认后删除）；
- 清空 `org/` 会丢失所有组织与智能体，操作前确认；
- 运行日志可定期清理 `runtime/logs/`。

## 常见问题

**Q：重启后组织/智能体还在吗？**
在。组织状态、会话历史都会持久化，重启后自动恢复。

**Q：磁盘占用涨得快？**
大头通常是 `workspaces/` 和 `runtime/logs/`，按上面的清理方法处理。

**Q：想同时运行多套独立环境？**
用不同数据目录启动多个实例（启动参数见[安装与启动](02-installation.md)），互不干扰。

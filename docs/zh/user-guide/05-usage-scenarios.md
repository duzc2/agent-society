# 使用场景与示例

本篇回答两个问题：什么任务适合交给它、怎么提需求效果最好。

## 信息收集

```
收集最近一周关于"多智能体系统"的十篇重要文章，
整理成一份 Markdown 报告，按主题分类，附原文链接
```

组织会拆出搜索、筛选、汇总等分工；中间结果写入工作区，最终报告发回给你。

> 说明数量、时间范围、产出格式，智能体会把这些写入任务的验收标准。


内置"内容运营"模板按策划、撰写、审校分工；产出文件落在工作区，直接取用。

## 长期使用

系统模拟企业管理：把每个组织当成一家公司来经营，唯一的区别是——智能体是虚拟员工，招聘和解聘的成本接近 0。为每一种工作设一个岗位，岗位上的智能体长期任职。

| 工作类型 | 岗位示例 | 长期用法 |
|----------|----------|----------|
| 日常信息收集 | 信息收集员 | 每天让它收集并汇总，它记得你关注的方向 |
| 内容创作 | 文案 | 持续产出，风格与历史保持一致 |
| 数据处理 | 数据分析 | 流程固定，处理新数据直接复用 |
| 客户沟通 | 客服 | 记录每次沟通，跟进历史问题 |

使用要点：

1. **同类工作固定同一岗位**：不用每次重新描述背景，在岗智能体记得之前的工作；
2. **工作量变化调整编制**：忙不过来时给岗位增加智能体，或给它配下级岗位分担；
3. **业务收缩减岗位**：不再需要的工作删除岗位，编制保持干净；
4. **新需求先给在岗者**：直接对现有智能体提新要求，让它判断是否需要找人协作。

## 需求写法

**好需求**：目标明确 + 产出形式清楚 + 约束边界清晰

```
在工作区创建 prices.xlsx 的分析报告 report.md：
1. 读取 prices.xlsx（我已上传到工作区）
2. 计算每月均价与波动率
3. 用 Markdown 表格呈现结果，并给出三条结论
```

**欠佳**：目标含糊、没有验收标准

```
帮我看看这个数据
```

**通用技巧**：

1. 说清"要什么"和"什么算完成"；
2. 需要的文件先上传到工作区，并在需求中提到文件名；
3. 大任务分阶段：先要方案，确认后再要实施；
4. 执行中补充信息用插话，比事后返工效率高。

## 常见问题

**Q：任务做到一半发现方向不对？**
直接插话纠正；影响大的话让智能体先停下来（Abort）重新对齐再继续。

**Q：复杂任务跑很久正常吗？**
正常。组织构建、多智能体协作、工具调用都需要时间。观察对话流确认它在推进即可。

**Q：同一类任务想固定用同一套组织？**
把任务说明和期望分工写进组织模板，Root 会参考模板组建。

**Q：想让某类工作长期由固定的智能体做？**
提需求时直接指定："这件事以后都交给 xxx"。智能体长期在岗，会记住这类工作的做法并沉淀为技能。

**Q：结果不满意怎么返工？**
直接说哪里不满意、期望什么，智能体在原组织上迭代；产出文件都在工作区，不会丢。

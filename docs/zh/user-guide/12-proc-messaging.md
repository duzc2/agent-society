# 进程协作（Proc 协议）

智能体能启动后台进程并与之双向通信，进程还能给你的界面组件提供数据。典型场景：智能体写一个数据服务并接管一个实时刷新的看板。

## 功能

```
你（界面看板） ◀── 实时数据 ─── 后台进程（智能体启动的）
                     ▲
智能体 ◀── 汇报消息 ──┘
   └── 指令 ──▶ 进程
```

三个通道：

1. **你 ⇄ 进程**：界面组件直接向进程要数据（HTTP 方式）；
2. **进程 → 你**：进程把进度、状态推送到界面；
3. **智能体 ⇄ 进程**：互相发消息，智能体下发指令、进程汇报结果。

## 使用

你不需要写代码——直接提需求：

```
做一个股票看板：后台每分钟抓一次数据，
前端实时刷新，放在我的界面上
```

智能体会自己完成全部接线：启动后台进程、生成界面组件、打通数据通道。

## 进程管理

- **查看进程**：侧栏 → 模块 → localcmd 面板，进程列表与输出控制台；
- **启停**：直接提需求（"把看板进程停掉"），或面板中操作；
- **进程退出**后相关数据通道自动清理，不影响界面其他部分。

进程长期运行即为长期服务：看板、定时任务这类工作由智能体建立后持续可用，不需要每次重建。

## 开发者须知

进程与系统的连接协议是纯 HTTP + JSON，任何语言可实现。协议细节与 SDK 见开发者文档的 [Proc 消息协议](../developer-guide/10-proc-protocol.md)——这部分内容面向开发者，普通使用不需要了解。

## 常见问题

**Q：看板不刷新了？**
进程可能已退出。在 localcmd 面板查看进程状态；重启进程后看板恢复。

**Q：进程的输出在哪看？**
侧栏 → 模块 → localcmd 面板：进程列表、输出控制台。

**Q：智能体能管理这些进程吗？**
能。启停、查看状态、发送输入都可以直接提需求完成。

**Q：两个任务启动了同名进程会冲突吗？**
会顶掉连接（后者接管）。建议提需求时让智能体用带任务特征的名字。

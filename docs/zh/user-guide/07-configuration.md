# 配置详解

大部分配置在**设置窗口**完成（侧栏 → 设置），无需接触文件。本篇覆盖需要手动编辑配置文件的情况。

## 配置方式

1. **推荐**：界面设置窗口修改，自动保存；
2. **手动**：编辑 `config/` 下的 `.local.json` 文件 → 重启服务器生效；
3. 不要编辑不带 `.local` 的模板文件，它们是系统预置模板。

| 文件 | 管什么 |
|------|--------|
| `config/app.local.json` | 端口、上下文限制、技能、记忆等系统参数 |
| `config/llmservices.local.json` | LLM 服务清单 |
| `config/modules.enabled.json` | 模块启停清单 |
| `config/modules/<模块名>.json` | 单个模块的参数 |
| `config/logging.json` | 日志级别 |

没有 `.local.json` 时，首次启动会自动从模板复制生成。

## 常用配置

### 端口

`app.local.json` 中的 `httpPort` 字段（默认 3000）。改完重启；也可启动时用 `--port` 参数临时指定。

### 上下文长度

`app.local.json` 中的 `contextLimit` 字段，`maxTokens` 与所用模型上下文上限一致即可。

长对话自动压缩历史，无需干预；压缩阈值一般不需要改。

### 日志

`logging.json` 中 `defaultLevel` 控制日志详细程度。排障时临时调为 `debug`；日志同时输出到控制台与日志目录。

## LLM 服务配置

见 [多模型配置](08-llm-services.md)——通常在设置窗口完成，无需手动编辑。

## 模块配置

- 启停：侧栏 → **模块**；
- 参数：如浏览器无头模式、代理，在模块管理窗口中设置。

## 常见问题

**Q：改了配置没生效？**
手动改文件后必须重启服务器；界面修改即时生效。

**Q：启动日志提示某条 LLM 服务配置不合法？**
该条服务被跳过，其余正常加载。按日志提示修正字段后重启。

**Q：配置文件改坏了？**
删掉对应 `.local.json`，重启后系统会从模板重新生成（注意：LLM 服务清单会回到模板状态，需重新填写）。

**Q：如何确认当前生效的配置来源？**
设置窗口顶部显示当前配置来源（本地/默认）。

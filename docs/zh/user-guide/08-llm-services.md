# 多模型配置

系统支持同时接入多个 LLM 服务：强模型做规划决策、快模型做日常执行、带视觉的模型处理图片。不同岗位自动用上合适的模型。

## 适用场景

- 想省成本：整理文件、格式转换这类简单活，用便宜的模型；
- 想要质量：架构设计、复杂分析，用更强的模型；
- 任务带图片/音频：需要声明了对应输入能力的模型；
- 某个服务限流或故障：还有别的服务可用。

只配置一个服务也能正常使用全部功能，多模型是优化项。

## 添加服务

侧栏 → **设置** → LLM 服务管理 → 新增，逐项填写：

| 字段 | 填什么 |
|------|--------|
| ID | 服务标识（英文），如 `gpt4`、`local-qwen` |
| 名称 | 显示名，如 "GPT-4"、"本地 Qwen" |
| Base URL | API 地址，以 `/v1` 结尾 |
| 模型名 | 如 `gpt-4o`、`qwen2.5-7b-instruct` |
| API Key | 云端服务必填；本地服务填 `NOT_NEEDED` |
| 能力声明 | 这个模型能收什么、能输出什么（见下） |
| 描述 | 一句话说明这个模型擅长什么 |

添加后可设为**默认服务**；未命中自动选模的任务都用默认服务。

## 能力声明

**输入能力**（这个模型能接收什么）：

| 选项 | 含义 |
|------|------|
| `text` | 文本（必选） |
| `vision` | 图片 |
| `audio` | 音频 |
| `file` | 文件 |

**输出能力**（这个模型能输出什么）：

| 选项 | 含义 |
|------|------|
| `text` | 文本回复（必选） |
| `tool_calling` | 能调用工具（**干活的岗位必须选有这项的模型**） |

填错会怎样：模型收不了图片，你发的图片会自动转成文字描述给别的模型处理；没有 `tool_calling` 的模型不会被派给需要动手干活的岗位。

## 自动选模

配置多个服务后，系统按岗位描述自动挑选模型。**岗位描述写得越具体，匹配越准**："负责编写 React 组件的工程师"比"写代码的"更容易配上合适的模型。

想固定某个岗位用某个模型：组织视图 → 岗位详情 → LLM 服务 → 手动指定。指定后不再自动选择。

## 验证

- 设置窗口的服务列表可见所有服务及其状态；
- 组织视图 → 岗位详情：查看该岗位当前用的模型和选择理由。

## 常见问题

**Q：添加服务后智能体没变化？**
选模结果记录在岗位上，旧的岗位沿用旧服务。新提交的需求、新创建的岗位使用新配置；或在岗位详情中手动切换。

**Q：报错"服务不可用/超时"？**
先在设置里确认服务状态；本地服务检查是否启动（如 LM Studio 是否在运行）；云端服务检查 API Key 与余额。

**Q：某岗位的任务老失败？**
检查该岗位所用模型是否支持工具调用（`tool_calling`）；不支持的话换一个支持的模型。

**Q：请求经常排队等待？**
并发数可在设置中调大；也可能是服务端限流，多个智能体同时请求时按队列逐个执行。

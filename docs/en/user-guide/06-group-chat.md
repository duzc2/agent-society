# Group Chat

Group chats let several agents (and you) talk in one place: every message reaches all members. Suited to multi-party discussion, brainstorming, and status sync.

## Creating a group

Sidebar → **Groups** → New → pick members; or just say it in chat:

```
Create a "release plan" group with the project manager
and the test lead
```

Members can be agents, or you.

## Group mechanics

- Any member's message is received and processed by all members;
- Joins, leaves, and dissolutions generate system messages;
- Your messages in the group get responses from member agents too.

## Usage examples

**Multi-party discussion:**

```
Create a "release plan" group with the project manager and
the test lead; have the project manager start the discussion
and send me the conclusion
```

**Ongoing sync:**

```
Create a "daily standup" group; have each lead post a
progress update there every day
```

**Arbitration:**

```
Frontend and backend disagree about the API format — put them
in a group to state their cases, then you decide and notify both
```

## Tips

1. **Keep membership small**: every message triggers processing in every member — more members, more traffic;
2. **Appoint a moderator**: one member aggregates and wraps up, keeping discussion from drifting;
3. **Write conclusions down**: have the moderator save final conclusions as a workspace document — more reliable than scrolling chat logs.

## FAQ

**Q: Too many group messages?**
Trim membership, or dissolve the group and switch to "owner reports to me" one-on-one updates.

**Q: Want a member out?**
Group details → remove member; or say "have xxx leave the group".

**Q: How long do groups persist?**
Groups and messages persist across restarts; dissolve unneeded ones in group details.

**Q: Who processes my message in a group?**
All member agents. For one recipient only, use a regular one-on-one conversation.

## P1：ProcMessageHub

**新文件：`src/platform/services/proc_messaging/proc_message_hub.js`**

1. `net.createServer()` 监听 `127.0.0.1:0`（随机端口），启动后端口暴露给 runtime（`runtime.procMessageHub`）与 spawn env 注入（P3）。
2. **握手**：每连接首条消息须为 `hello{token, name, agentId}`；校验 token 与 spawn 记录（token 注册表由 spawn 提供，P3 衔接）；失败 → log.warn + 关闭。
3. **注册表**：`<name>#<agentId>` → `{ socket, procName, agentId, connectedAt }`；同名重复连接 → 关闭旧连接保留新。
4. **inbound 路由**：
   - `msg` → `bus.send({ to: msg.to ?? agentId, from: "proc:<name>#<agentId>", payload, extras: { kind: "proc_msg", procName } })`
   - `event` → `heartbeatBroker.broadcast("proc_event", {...}, 60_000)`
   - `error` → 同 event + `log.error`
   - 其他类型 → log.warn（RPC 二期）
5. **outbound**：`sendToProc(addr, payload)` → 查注册表写 socket（JSONL）；无连接 → `{ error: "proc_offline" }`。
6. **生命周期**：socket close/error → 注销；`shutdown()` → 关 server + 全部断开。
7. 挂载：`bootstrap_manager.js` 初始化（同 heartbeatBroker 模式），`runtime.js` 暴露。

**测试（`test/platform/proc_message_hub.test.js` 新建）**：握手成功/失败（错 token 关闭）；msg → bus.send 参数正确；event → heartbeat broadcast；断开注销；同名连接替换；总线关闭清理。

**验收：** `npm test` 全绿；停下汇报。

## P2：Node SDK + 协议文档

**新文件：`sdk/proc_client.js`、`docs/proc-messaging-protocol.md`**

1. `createProcClient({ name, agentId? })`：
   - 读 `process.env.SOCIETY_PROC_HUB_PORT` / `SOCIETY_PROC_TOKEN`（缺省则报错提示"需经 agent-society spawn 启动"）
   - `net.connect` → 发 `hello` → 等 `welcome`（超时 5s 报错）
   - 暴露：`onMessage(cb)`、`onEvent(cb)`、`onError(cb)`、`send(payload)`（to 缺省为当前 agent）、`notifyWeb(event, data)`、`close()`
   - 断线重连：指数退避 1s→2s→…→30s；重连重新 hello
2. 协议文档：信封/类型/握手/重连/示例（Node 用法 + 手写 Python 示例）/安全（token）。
3. SDK 为纯 Node 内置模块（`net`/`readline`），无新依赖。

**测试（`test/sdk/proc_client.test.js`）**：mock TCP server 模拟 hello/welcome/msg/event；重连退避（fake timers）。

**验收：** `npm test` 全绿；停下汇报。

## P3：spawn env 注入 + 智能体接入

**改：`modules/localcmd/process_manager.js`**：spawn 的 env 合成处注入 `SOCIETY_PROC_HUB_PORT`（runtime.procMessageHub 端口）与 `SOCIETY_PROC_TOKEN`（每次 spawn `randomUUID()`）；hub 侧 token 注册表同步登记（`hub.registerSpawn({ token, agentId })`，spawn 时调用、exit 时清理）。**普通进程无感**（env 多了两个变量而已）。

**改：`modules/localcmd/tools.js`（或新工具组）**：`proc_send` 工具：`{ target: "proc:<name>#<agentId>" | <name>, text?: string, payload?: object }` → hub.sendToProc → `{ ok }`/`{ error: "proc_offline" }`。

**改：formatter 注册**（`modules/localcmd/index.js` init 或 hub 模块）：`registerMessageFormatter(predicate kind==="proc_msg", formatter)` → `【进程消息·<procName>】<payload.text 摘要 500>`。

**测试：** spawn env 注入（mock 断言 env）；proc_send（target 解析/离线错误）；formatter 单测；现有 localcmd 测试回归（env 增量无行为变化）。

**验收：** `npm test` 全绿；停下汇报。

## P6：构建 + 端到端验证

1. `bun scripts/build-web.mjs v3`；`npm start`。
2. **进程协议主闭环**：智能体 `localcmd_spawn` 一个 SDK 进程（示例 `sdk/examples/crawler.js`：订阅消息、定时 notifyWeb progress、hello 注册）→
   - 面板进程列表显示"协议已连接"→ 消息流出现 `progress` 事件滚动
   - 面板发送 `{ target, payload }` → 进程 SDK `onMessage` 收到并回执（进程回 `msg` → 智能体会话出现【进程消息·crawler】）
   - 智能体 `proc_send` → SDK 收到
   - 杀掉进程 → 面板消息流状态"离线"；重启（SDK 重连）→ 自动恢复
3. **普通进程回归**：spawn `python -c "print('hi')"`（无 SDK）→ 面板文本输出、stdin 输入、事件推送均照旧。
4. **A/B 通道**（沿用 v2 验证清单）：`__notify` → 聊天记录；`ui_page_notify` → CustomEvent；长 RPC 关页保活重投。
5. **安全**：无 token 手连 hub 端口 → log.warn + 关闭。
6. 全绿后按项目规范提交。

## 风险与回退

| 风险 | 应对 |
|---|---|
| hub 与 spawn 的 token 注册共享时序 | 注入 env 前先 `hub.registerSpawn`；exit 事件清理；不匹配则拒绝连接 |
| SDK 重连风暴 | 指数退避 + 同 token 并发连接只留最新 |
| 面板同时显示两类进程状态复杂 | 协议/普通分栏；普通进程逻辑完全复用 v2 设计 |
| 对现有 localcmd/remote 测试影响 | spawn env 注入纯增量；P3 回归测试把关 |
| proc_msg 进会话刷上下文 | formatter 截断 + 与页面通知同语义（对话消息），事件类走 event 不进会话 |
